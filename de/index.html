BETRIEB

Lokal starten.
Teilen, wie Sie wollen.

Lokal. Im Team. Veröffentlicht. Sie entscheiden.

Alle vier sind Teil des ersten Releases.
01Nur Sie, lokal

Sie öffnen Hanji, den Rest macht der Willkommensbildschirm: ein Name für den Ort, Ihr Passwort, Ihr Markdown-Ordner.

# ab dem Release öffentlich:
git clone https://github.com/gethanji/hanji
pnpm install && pnpm dev:web
Der Fünf-Minuten-Start
02Ihr Team, im Tailnet

Eine gemeinsame Instanz, bei der das Netzwerk die Anmeldung übernimmt. Niemand tippt ein Passwort. Die Berechtigungen bleiben genau so, wie Sie sie vergeben haben.

export HANJI_TAILSCALE_OWNER=you@github
next start -H 127.0.0.1 -p 4100
tailscale serve --bg 4100
Im eigenen Tailnet betreiben
03Mit Ihren Coding-Agenten

Eingeschränkter Lesezugriff über MCP oder einfaches HTTP. Ein Bash-Skript mit curl zählt als Agent. Änderungen kommen als Vorschläge und warten auf Ihre Entscheidung.

pnpm hanji token my-claude notes=read+propose
# Agent mit dem ausgegebenen Token anbinden.
Ihrem Agenten einen Schlüssel geben
04Im Web veröffentlicht

Alles, was Sie für alle freigegeben haben, als statische Website. Eine Markdown-Fassung und llms.txt kommen mit. Das Handbuch ist genau so veröffentlicht.

pnpm hanji rule handbook everyone-read
pnpm hanji export ./site
Einen Teil öffentlich machen
